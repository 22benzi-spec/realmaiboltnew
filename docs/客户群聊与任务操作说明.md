## 2. 客户库：多群聊名称

### 2.1 业务规则

- 反馈方式为「群聊」时，可维护多个群聊名称。
- 添加 / 编辑可增删群名（首行右侧 `+`，多余行可删）。
- 详情只读展示：有多少群名显示多少标签，不可在详情内编辑。
- 私聊时不展示群名输入；保存时 `group_names` 置为空数组。

### 2.2 存储

| 表 | 字段 | 说明 |
|----|------|------|
| `client_companies` | `feedback_type` | 私聊 / 群聊 |
| `client_companies` | `group_names` | `text[]`，多个群聊名称 |

保存时一并写入 `feedback_type` 与规范化后的 `group_names`（去空、trim）。

### 2.3 注意

- 需先在数据库执行 `group_names` 迁移，否则读写该字段会失败。

## 3. 创建任务：关联客户多群聊选择

### 3.1 下拉展示规则

加载活跃客户时读取 `feedback_type`、`group_names`：

| 条件 | 下拉表现 |
|------|----------|
| 群聊且群名 ≥ 2 | 同一公司拆成多行，显示「公司名 · 群名」 |
| 私聊，或群聊仅 1 个群名 | 只显示公司名（不展示群名） |

### 3.2 选中后写入任务（`erp_orders`）

| 字段 | 群聊时 | 私聊时 |
|------|--------|--------|
| `customer_name` | 公司名 | 公司名 |
| `customer_id_str` | 公司 `org_id` | 同左 |
| `feedback_channel` | `群组`（订单侧既有口径） | `私聊` |
| `group_name` | 选中的群名；单群时虽不下拉展示也会静默带上唯一群名 | 空 |

`company_id` 仍为公司 UUID，用于加载历史店铺 / ASIN。

### 3.3 前端演示数据（预览用）

`OrderFormView` 内合并 mock 客户，便于无库数据时看效果：

| 搜索关键词 | 预期 |
|------------|------|
| `测试公司` | 三行：测试公司 · 群聊1 / 群聊2 / 群聊3 |
| `测试单群公司` | 仅一行公司名（不展示群名） |

Mock 的 `company_id` 非真实库记录，**不宜当真提交任务**。确认真实数据可用后可去掉 mock。

## 4. 任务管理：操作菜单

### 4.1 入口位置

任务卡片操作区：「复制」之后为「操作」下拉（原独立「追加订单」按钮已收进菜单）。

### 4.2 菜单内容（自上而下）

1. **追加订单**（第一项）  
   - 仅关闭菜单并调用原有 `openAppendModal(record)`。  
   - **追加订单弹窗本身无改动**。

2. 分隔线后三个布尔开关（`a-switch`，文案「是 / 否」）：

| 界面文案 | 字段 | 表 |
|----------|------|----|
| 每日反馈 | `daily_feedback` | `erp_orders` |
| 金额图片 | `comprehensive_label` | `erp_orders` |
| 单号图片 | `delivery_label` | `erp_orders` |

切换后立即 `update` 对应布尔字段；成功 / 失败有提示，失败回滚本地显示。

### 4.3 注意

- 创建任务页当前表单默认带有上述三个布尔字段，但页面上未必有录入 UI；任务管理「操作」用于事后切换。
- 若字段中文与库字段对应有误，只改 `taskFlagOptions` 映射即可。
