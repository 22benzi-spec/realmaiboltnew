# 接单列表 · 基础入账 / 尾款 / 结算 三维度说明（给技术）

> 落地页：`#/my-orders` → `src/views/orders/index.vue`  
> 辅助：`src/views/orders/helpers.ts`、`prototypeService.ts`、`types.ts`  
> 单笔账单：`src/views/orders/components/BillingDrawer.vue`  
> 日期：2026-11-23  
> 性质：**产品口径 + 原型展示层**；`payment_status=4` 暂映射「已结算」，建议正式拆独立结算字段。

---

## 1. 改动目的

把原来混在「账款情况 / 款项情况 / 已结清」里的三件事拆开：

| 维度 | 回答的问题 |
|------|------------|
| 基础入账 | 基础款入完了没有？有没有基础层溢余？ |
| 尾款 | 任务差价现在是欠、余，还是没事？ |
| 结算 | 要不要办结、办完没有？ |

列表用**三个独立筛框**（可交叉），列与账单文案与三维度对齐。

---

## 2. 字段与枚举（现状存储）

### 2.1 基础入账 `bill.basic_bill_status`

| 值 | 展示 | 说明 |
|----|------|------|
| 1 | 已完成 | 基础入账完成 |
| 2 | 未完成 | 基础未入完；可配 **待收** 金额 |
| 3 | 富余 | 基础实收多于应付；可配 **富余** 金额 |

金额（组/单任务挂在 `task_basic`）：

- `basic_entry_amount_cny` / `basic_entry_amount_usd`
- 未完成 → 金额跟在状态后，文案 **待收 ¥…**（不另起「待收」行）
- 富余 → 金额跟在状态后，**只显示金额**（不重复写「富余」）

### 2.2 尾款（原「账款情况」）`bill.payment_status`

| 值 | 展示 | 说明 |
|----|------|------|
| 1 | 无异常 | **系统判定**；正式环境不应靠手改回到无异常 |
| 2 | 有欠款 | 任务尾款还要收；金额 `arrears_amount` / `arrears_usd_amount` |
| 3 | 有余款 | 任务尾款需退/溢 |
| 4 | 已结算（原「已结清」） | **结算结果**，不再当尾款枚举展示 |

### 2.3 结算状态（展示层推导；筛选用 `settlement_status`）

| 值（筛） | 展示 | 判定 |
|----------|------|------|
| 1 | 无需补退 | `basic_bill_status=1` 且 `payment_status=1` |
| 2 | 未结算 | 非已结算，且非无需补退 |
| 3 | 已结算 | `payment_status=4` |

列表默认：

- **无需补退 / 未结算**：不在「基础款与结算」列刷标签（可筛）
- **已结算**：在「基础款与结算」列显示绿色「已结算」

## 3. 核心逻辑（状态机）

### 3.1 结算怎么算

```
if payment_status == 4:
    结算 = 已结算
else if basic_bill_status == 1 and payment_status == 1:
    结算 = 无需补退
else:
    结算 = 未结算
```

因此：入账=未完成或富余时，即使尾款=无异常，结算也是 **未结算**。

### 3.2 尾款怎么展示

```
if 结算 == 已结算:
    尾款展示 = "-"          // 不再显示「无异常」
else if 有欠款:
    尾款展示 = 有欠款 + 金额
else if 有余款:
    尾款展示 = 有余款 + 金额
else:
    尾款展示 = 无异常
```

产品确认：无异常只能系统判；已结算后尾款固定 `-`。

代码：`getSettlementStatus` / `getTailStatusKind`（`helpers.ts`）。

### 3.3 列表列

**「基础款与结算」**（原「实收基础款项」），最多四行：

1. 基础实收金额（`task_basic.actual_*`）
2. 基础入账状态
3. 待收/富余金额贴在入账状态后（有值才出；富余不重复写「富余」）
4. 「结算状态：已结算」（仅结算=已结算；带前缀）

**「尾款状态」**（原「款项情况」）：只展示尾款（含 `-`），不再展示已结清标签。

## 4. 筛选（方案一：三框）

| 筛框 | 选项 | 参数 |
|------|------|------|
| 基础入账 | 未完成 / 已完成 / 富余 | `basic_bill_status` |
| 尾款状态 | 无异常 / 有欠款 / 有余款 | `payment_status`（**不含 4**） |
| 结算状态 | 无需补退 / 未结算 / 已结算 | `settlement_status`（原型；正式需后端支持或独立字段） |

可交叉，例如：入账已完成 ∧ 有欠款 ∧ 未结算。

原型过滤：`prototypeService.filtered` + `settlementOf(row)`。  
真接口若尚未支持 `settlement_status`，需后端补参数或前端仅原型生效——对接时以契约为准。

## 6. 验证 Mock（SEED_VERSION=4，任务号）

| 任务号 | 预期 |
|--------|------|
| `TASK-SETTLE-NONEED-001` | 无需补退；尾款无异常；列不显示结算字 |
| `TASK-SETTLE-OWED-001` | 未结算；有欠款 |
| `TASK-SETTLE-SURPLUS-001` | 未结算；有余款 |
| `TASK-SETTLE-DONE-001` | 列显示已结算；尾款 `-` |
| `TASK-SETTLE-SHORT-001` | 入账未完成 + 待收金额；未结算 |
| `TASK-SETTLE-BASESURP-001` | 入账富余 + 金额（不重复「富余」）；未结算 |
| 组待收/组富余演示 | 组级待收/富余金额贴在入账状态后 |

本地 IndexedDB 会因 `SEED_VERSION` 变更重建。筛「结算=已结算」应出 DONE；筛「尾款=无异常」不应出 DONE。

## 7. 正式环境建议（未做）

1. 新增 `settlement_status`（或等价），写已结算时不要只靠 `payment_status=4`。
2. 尾款枚举收窄为 1/2/3；4 仅历史兼容。
3. 无异常禁止业务员手改回退；纠错走作废/纠错单。
4. 列表/统计接口支持 `settlement_status` 筛选。
5. 组账单内嵌表已改为尾款状态/金额，并在基础入账后展示待收/富余额；其它弹窗若仍有「差价」旧文案可另开任务清扫。
