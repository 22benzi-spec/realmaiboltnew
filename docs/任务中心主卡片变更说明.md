# 任务中心 · 主卡片字段同步与变更提示说明

> 文档依据当前代码实现整理，对应页面：`src/views/TaskManagementView.vue`。  
> 原型项目：主订单读 `erp_orders`，子订单读写 `sub_orders`；变更历史以前端 `localStorage` + 页面 mock seed 为主（方案 A，不回写主订单展示字段）。

---

## 1. 页面定位与入口

### 1.1 业务含义

任务中心「任务列表」展示主任务卡片。子订单修改类型、等级、ASIN、售价后，主卡片需同步展示最新结果；任务总量左侧数字保持原计划不变，实际子单变化看右侧次卡片「子订单」数。曾被修改的字段在右上角显示小红点，点击可查看该字段变更记录。

### 1.2 入口

| 入口 | 路径 / 位置 | 说明 |
|------|-------------|------|
| 任务中心 → 任务列表 | `#/task-management`，导航「任务中心」 | 主入口，页面标题「任务中心」，Tab「任务列表」 |

### 1.3 组件与依赖

| 项 | 说明 |
|----|------|
| 主页面 | `src/views/TaskManagementView.vue` |
| 主订单表 | Supabase `erp_orders` |
| 子订单表 | Supabase `sub_orders` |
| 变更历史存储 | `localStorage` key：`task_management_order_edit_history_v3` |
| Mock seed | 页面内 `ORDER_EDIT_HISTORY_SEED`（`mock_order_pending_a` / `mock_order_pending_b`） |

---

## 2. 主卡片字段展示规则

仅描述本次「主卡片同步 + 角标」相关字段；其余主卡片信息（国家、客户、商务等）仍读主订单原字段。

| 字段 | 展示规则 |
|------|----------|
| 等级 | 取子单中最新一条的 `review_level`；无子单时用变更记录最新值，再回退主订单。高等 / 极高等常显；有变更记录时普通等级也会显示以便看角标 |
| 类型 | 子单中同时存在「免评」与留评类（文字 / 图片 / 视频 / Feedback）时显示「混合」；否则显示最新类型（一个值） |
| ASIN | 取子单最新一条；无子单时用变更记录最新值，再回退主订单 |
| 售价 | 有售价变更时显示「初始售价-最新售价」（如 `$15.99-$19.99`）；中间多次变更不在主卡片展开，点角标查看 |
| 任务总量 | **始终显示**主订单 `order_quantity`，追加订单也不改此数字；实际增加看右侧「子订单」统计 |

「最新」口径：已加载子单时按 `updated_at`（无则 `created_at`）取最新一条；未加载子单时优先用该字段变更历史的最新 `to`。

## 3. 角标与轻量变更弹窗

### 3.1 范围

只做在主卡片上，子订单表格行不加角标。

涉及字段：`review_type`（类型）、`review_level`（等级）、`asin`、`product_price`（售价）、`order_quantity`（任务总量）。

### 3.2 交互

- 字段曾出现在变更历史中时，右上角显示约 6px 红色圆点。
- 点击圆点打开 Popover（不触发展开/收起主卡片）。
- 弹窗结构：
  - 第一行：`时间 · 操作人`
  - 第二行：`字段：旧值 -> 新值 X单`  
    示例：`测评类型：文字 -> 图片 5单`

### 3.3 被修改单量

取该条历史记录的 `affected_sub_count`，拼在变更正文末尾，格式为 ` {n}单`。

## 4. 变更历史来源与写入时机

| 来源 | 说明 |
|------|------|
| `localStorage` | key `task_management_order_edit_history_v3`，按主订单 id 存列表 |
| 页面 seed | 无本地记录时注入 `ORDER_EDIT_HISTORY_SEED`，含同一字段多次修改的 mock |
| 快捷编辑 / 批量修改子单 | 成功后 `appendTaskEditHistory` |
| 子订单详情保存 | 类型、售价有变化时写入历史 |
| 追加订单 | 写入 `order_quantity` 历史（from/to 为追加前后子单总数）；**不**更新主订单 `order_quantity` / `total_orders` |

详情抽屉内原有「修改记录」时间线仍保留，与主卡片角标共用同一套历史读取逻辑。

---

## 5. 追加订单与右侧次卡片

| 项 | 行为 |
|----|------|
| 左侧「任务总量」 | 保持追加前的 `order_quantity` |
| 右侧「子订单」 | `_sub_total` 随追加增加 |
| 主订单库表 | 追加成功后仅更新状态为「进行中」等，不再把总量写回 `order_quantity` |
| 角标 | 追加会产生任务总量变更记录，左侧总量数字不变，角标可点开查看 |

---

## 6. Mock 说明（多次修改）

`ORDER_EDIT_HISTORY_SEED.mock_order_pending_a` 覆盖示例：

- 类型：`文字 -> 图片 5单`、`文字 -> 免评 2单`（可演示「混合」相关场景与多条记录）
- 售价：多次调价，主卡片只显示初始-最新大区间
- ASIN / 等级 / 任务总量：各有不少于 2 次变更

若浏览器仍缓存旧 key `task_management_order_edit_history_v2`，需清该 key 或依赖新 key `v3` 后刷新，才能看到新 seed。

## 7. 相关函数（便于定位）

| 函数 | 作用 |
|------|------|
| `getMainCardAsin` / `getMainCardReviewLevel` / `getMainCardTypeLabel` / `getMainCardPriceText` | 主卡片展示值 |

| `appendTaskEditHistory` | 写入并持久化变更历史 |
| `saveAppendOrders` | 追加子单；总量不回写主订单 |

---

## 8. 修改边界

- 本次能力仅限任务中心任务列表主卡片；不扩散到抢单大厅、订单列表等页面。
- 方案 A：不把聚合展示结果回写 `erp_orders` 的 ASIN / 售价 / 类型等字段。
- 共享组件未改；样式仅增加主卡片角标与 Popover 相关 class。
