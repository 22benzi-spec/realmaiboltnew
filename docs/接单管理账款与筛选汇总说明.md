# 接单管理 · 账款抽屉与筛选汇总说明

> 文档依据当前代码实现整理。  
> 对应页面：`src/views/OrderListView.vue`  
> 关联组件：`src/components/BillingDrawer.vue`、`src/components/GroupBillingDrawer.vue`  
> 原型项目：主订单读写 `erp_orders`，流水读写 `batch_payments`；详情无真实流水时用页面 mock 渲染。

---

## 1. 页面定位与入口

### 1.1 业务含义

接单管理列表用于查看与筛选主任务（`erp_orders`），并处理单笔 / 批量账款：核对实际应收、累计入账、差价与账款情况，录入补款 / 账面抵消 / 退款。有搜索或筛选时，表格底部展示**筛选结果全集**的合计（不是当前页）。

### 1.2 入口

| 入口 | 路径 / 位置 | 说明 |
|------|-------------|------|
| 接单中心 → 接单管理 | `#/my-orders`，导航「接单管理」 | 主入口，页面标题「接单管理」 |

### 1.3 组件与依赖

| 项 | 说明 |
|----|------|
| 主页面 | `src/views/OrderListView.vue` |
| 单笔账款抽屉 | `src/components/BillingDrawer.vue`（宽度 680） |
| 批量 / 任务组账款抽屉 | `src/components/GroupBillingDrawer.vue`（宽度 1100） |
| 主订单表 | Supabase `erp_orders` |
| 流水表 | Supabase `batch_payments`（按 `batch_id` = 订单 id） |
| 路由 | `src/router/index.ts` → `/my-orders` |

## 2. 列表筛选合计（有筛选才显示）

### 2.1 出现条件

以下任一有值时显示 summary 行（`hasActiveFilters`）：

- 搜索框（任务号 / ASIN / 店铺 / 产品名）
- 状态 / 国家 / 下单类型 / 账款状态筛选

无筛选时不显示合计行。

### 2.2 汇总口径（筛选全集，非当前页）

`loadFilterSummary` 按与列表相同的过滤条件分页拉取全部匹配行（每批 1000），再汇总：

| 展示位置（相对列） | 指标 | 计算 |
|--------------------|------|------|
| 测评类型/量 下 | 总接单量 | `order_quantity` 求和 |
| 佣金 下 | 佣金总额 | 单类型：单价 × 数量；多类型：各类型数量 × 对应单价 |
| 应收基础款项 下 | 应收基础款项合计 | `total_amount` 求和 |
| 实收基础款项 下 | 实收基础款项合计 | 关联 `batch_payments`：退款记负，其余记正 |
| 账款状态 下 | 账款状态有符号合计 | `debt_status === 'owed'` 为负、`surplus` 为正，取 `debt_amount`；其它为 0 |

另显示「筛选 N 条」（匹配订单条数）。

### 2.3 表头吸顶

表格 `scroll.y = calc(100vh - 280px)`，并配合 thead sticky 样式，纵向滚动时表头固定。

## 3. 详情抽屉 · 资金汇总

打开订单详情后，「资金汇总」字段：

| 字段 | 含义 / 规则 |
|------|-------------|
| 实际应收 | 优先用订单上的 `actual_receivable`（前端合并值）；否则 `total_amount` ± 差价（欠款加、溢收减） |
| 累计实收 | 基础收款 + 补款 |
| 账面抵消 | `payment_type === '账面抵消'` 合计 |
| 待结算差额 | `累计入账 − 实际应收`；`累计入账 = 累计实收 + 账面抵消 − 累计退款`；`debt_status === 'cleared'` 时强制为 0 |
| 累计退款 | 仅当存在退款流水时显示 |

无真实流水时用 `mockBatchPayments`：`debt_status === 'surplus'` 时带退款 mock，否则不带退款。

## 4. 单笔账款抽屉（BillingDrawer）

### 4.1 顶部三指标

- **实际应收** / **累计入账** / **待结算差额**
- 编辑实际应收时，顶部与表单共用展示值；待结算差额随编辑即时变化
- `debt_status === 'cleared'` 时待结算差额为 0

### 4.2 账款状态区块

| 字段 | 说明 |
|------|------|
| 实际应收 | 默认可编辑；默认值为系统计算（基础应收 ± 差价）；**不**因修改实际应收自动改差价金额 |
| 基础入账状态 | 查看态字段名下提示「人工修改」；对应 `billing_status` |
| 账款情况 | 查看态字段名下提示「人工计算」；对应 `debt_status` / `debt_amount` |
| 差价金额 | 仅账款情况为「客户需补款 / 需退客户」时编辑 |

查看态提示只出现在字段名下方，不挂在标签上；进入编辑态后提示隐藏。已去掉「差额备注 / 标记商务」编辑入口（保存时仍可能沿用订单原有 `debt_notes` / `debt_marked_*` 字段写入逻辑）。

### 4.3 实际应收持久化说明

- 保存时更新 `erp_orders` 的 `billing_status`、`debt_status`、`debt_amount` 等
- `actual_receivable` 通过 `emit('updated')` 合并进列表 / 当前订单内存
- **当前库表无独立 `actual_receivable` 列时，刷新后覆盖值会丢失**，需以后端字段落地后才能跨刷新保留

## 5. 批量账款抽屉（GroupBillingDrawer）

### 5.1 顶部汇总

- **实际应收** / **累计实收** / **账面抵消** / **待结算差额**
- 有退款流水时额外显示 **累计退款**
- 存在差价任务时警示：`含 N 个任务存在差价，请及时处理`（警示条宽度随内容）

### 5.2 账款核对与处理（原「账款一览」+「合并款项录入」合并）

标题旁显示 `N 个任务`。

表头列：

创建时间 | 任务编号 | Asin | 实际应收 | 累计入账 | 基础入账状态 | 账款情况 | 差价金额

- **累计入账**（行级）= 该单累计实收 + 账面抵消
- 行内可改基础入账状态、账款情况、差价金额并即时保存
- 顶部批量选择占位为「基础入账状态」「账款情况」，无默认枚举；点「批量应用」时至少选一项

底部合计：

- 总实际应收 / 总累计到账 / 总差价（并带差价状态文案：客户需补款 / 需退客户 / 无异常）

操作按钮（由账款情况 + 有效差价驱动）：

- **录入补款**、**账面抵消**：存在欠款差价合计 > 0 时可点
- **提交退款**：存在溢收差价合计 > 0 时可点

差价金额为空时，有效差价可回退为「实际应收 − 累计入账」的差额（`getOrderEffectiveDiffAmount`）。

抽屉宽度 **1100**，表格通栏展示。

## 6. 关键计算对照

| 名称 | 公式 / 规则 |
|------|-------------|
| 累计入账（单笔 / 详情） | 累计实收 + 账面抵消 − 累计退款 |
| 累计入账（批量行「累计入账」列） | 该单实收类流水 + 账面抵消（不含减退款的展示口径见组件） |
| 待结算差额 | 累计入账 − 实际应收；已结清为 0 |
| 筛选账款合计 | 欠款负、溢款正，取 `debt_amount` |

## 8. 修改边界

- 本次能力范围：接单管理列表筛选合计、详情资金汇总文案与计算、单笔账款抽屉、批量账款抽屉。
- 不扩散到任务中心、抢单大厅、其它列表页的同类字段，除非另行授权。
- `BillingDrawer` / `GroupBillingDrawer` 若被其它入口引用，改动会一并生效；当前主入口为接单管理。
- 未新增数据库列；`actual_receivable` 跨刷新持久化需单独排期。
