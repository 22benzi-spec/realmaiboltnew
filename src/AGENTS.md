# 前端模块说明

## 模块范围

- 本目录包含 ERP 的 Vue 页面、共享组件、路由、状态组合逻辑和前端数据交互。
- 当前项目属于业务原型项目，页面需优先保证业务流程、状态展示和 mock 交互可直观看到。
- 页面使用 Vue 3 Composition API、TypeScript、Ant Design Vue、Supabase 和 Day.js。

## 修改边界

- 只修改用户明确指出的页面、菜单或业务模块，禁止把相似页面自动纳入同步范围。
- 修改被多个入口共用的组件前，必须先列出受影响的页面和菜单，并确认是否允许全部生效。
- 未获得全部生效授权时，应通过页面参数、插槽或局部封装隔离改动，禁止影响其他引用入口。
- 发现范围外问题只能说明，不得顺手修改。

## 业务实现

- 修改订单、子订单、返款或售后状态前，先查清现有枚举、格式化逻辑、保存字段和 mock 数据口径。
- 展示文案与保存值不一致时，必须明确区分；禁止只改界面文字造成底层状态混乱。
- 用户要求查看交互效果时，应提供能进入目标状态的 mock 或预览数据，并保证刷新后仍可验证。
- 共用编辑能力应保持字段含义和保存结果一致；不同页面的按钮、步骤和布局差异必须有明确业务原因。

## 页面与样式

- 页面样式遵循项目主题，不新增无来源的主色、状态色或背景色。
- 优先减少重复说明和重复编辑入口；同一字段在同一流程中只保留一个清晰修改入口。
- 表格、弹窗和抽屉修改后，应检查内容层级、滚动、关闭方式和操作按钮是否清楚可见。

## 验证要求

- 代码修改后至少执行相关文件诊断，并按风险运行类型检查或构建。
- 页面改动必须进入对应菜单，用目标 mock 或真实数据验证显示、编辑、关闭和提交前交互。
- 未实际验证的内容必须明确说明，禁止仅凭构建通过宣称页面效果正确。
