# 售后问题单（问题单售后）全量说明

> 文档依据当前代码实现整理，对应组件：`src/components/AfterSaleIssueList.vue`。  
> 原型项目含 mock 数据与 Supabase 表读写；部分字段以 mock / 前端状态为主。

---

## 1. 页面定位与入口

### 1.1 业务含义

售后问题单用于业务员处理子订单售后异常：补单、替换单号、转交、抢单大厅、追回本金、关闭、无需处理、撤销等，并维护本金状态与处理进度。

### 1.2 入口

| 入口 | 路径 / 位置 | 说明 |
|------|-------------|------|
| 业务员工作台 → 问题单售后 | `#/staff-workbench`，导航键 `afterSale` | **当前主入口**。`StaffWorkbenchView` 内嵌 `AfterSaleIssueList`，可传 `staff-id`、`show-stats` |
| 独立页「售后问题单」 | `AfterSaleView.vue` | 组件复用同一列表；路由 `/after-sale` 在 `src/router/index.ts` 中**当前为注释状态**，默认菜单不可直达 |

### 1.3 组件与依赖

| 项 | 说明 |
|----|------|
| 主组件 | `src/components/AfterSaleIssueList.vue` |
| 补单编辑 | 复用 `SubOrderWorkflowEditor.vue`（补单弹框） |
| 数据 | Supabase 表 `after_sale_issues` + 本地 mock（`localStorage`，key：`mock_after_sale_issue_list_v11`） |
| 关联表 | 补单/换号时可能读写 `sub_orders`；业务员选项来自 `staff`；买手来自 `erp_buyers` |

### 1.4 Props / 事件

| Props | 类型 | 默认 | 说明 |
|-------|------|------|------|
| `staffId` | string | - | 按业务员过滤 |
| `issueId` | string | - | 只看指定问题单 |
| `subOrder` | string | - | 用子订单号等作为搜索词 |
| `showStats` | boolean | true | 是否展示顶部概览 |

| 事件 | 说明 |
|------|------|
| `changed` | 保存/删除等变更后触发，工作台用于刷新统计 |

## 2. 顶部数据概览（`showStats=true`）

时间范围默认近 30 天（含起止日），与列表共用筛选时间。

| 指标 | 口径（代码） |
|------|----------------|
| 问题单量 | 当前时间范围内条数 |
| 处理中 | 进度主状态为「处理中」的数量；副文案含无新单号条数 |
| 今日已处理 | 判定为已处理，且 `resolved_at` 或 `updated_at` 为今天 |
| 本金损失金额 | 本金状态为「已损失」的金额合计与单量 |

## 3. 筛选栏

从左到右：

| 筛选项 | 枚举 / 行为 |
|--------|-------------|
| 国家 | 美国、德国、英国、加拿大。兼容旧值 `US/DE/UK/CA/USA/GB` |
| 订单状态 | 不下单、取消、退款、无此订单、本金多返（对应字段 `issue_type`） |
| 处理进度 | 待处理；处理中（含全部处理中子态）；处理中-转给他人；处理中-无新单号；处理中-抢单大厅；已处理 |
| 处理结果 | 替换单号、补单、追回本金、无需处理、已关闭（筛到结果态时会包含已关闭类数据） |
| 本金状态 | 正常、待确定、待追回、已追回、已损失 |
| 搜索 | 订单号 / 订单ID / 买手 / 客户 / ASIN 等 |
| 导出 / 刷新 | CSV 导出当前筛选结果；刷新重载 |

### 3.1 默认列表范围

未选「处理进度」且未选「处理结果」时：只展示进度**不是**「已处理」的单据（待处理 + 处理中一类）。  
选「已处理」或「处理结果」时可看到结果态单据。

### 3.2 处理进度筛选项含义

| 选项 | 含义 |
|------|------|
| 待处理 | 主进度 = 待处理 |
| 处理中 | 主进度 = 处理中（含转给他人 / 无新单号 / 抢单大厅及普通处理中） |
| 处理中-转给他人 | 处理中，且 `transfer_to_staff` 有值且不等于 `GRAB_HALL` |
| 处理中-无新单号 | `issue_status` 规范后为「无新单号」 |
| 处理中-抢单大厅 | 处理中，且 `transfer_to_staff === 'GRAB_HALL'` |
| 已处理 | 满足「已处理」系统判定（见第 7 节） |

## 4. 一级列表

### 4.1 列

| 列 | 内容 |
|----|------|
| 产品信息 | 品名、ASIN、国家 |
| 订单信息 | 原亚马逊订单号、子订单ID；可点开详情 |
| 客户/商务 | 客户名、商务 |
| 业务员 / 买手 / 聊单号 | 业务员、买手、聊单号 |
| 返款信息 | 实返金额、实付、返款方式展示 |
| 订单状态 | `issue_type` 标签 |
| 本金状态 | 标签；若有金额则标签下展示金额（见 4.2） |
| 售后进度 | 主进度标签 + 可选标识（转给他人 / 无新单号 / 抢单大厅）；未已处理时可点选编辑 |
| 备注 | `resolution_notes` |
| 下单时间 | `amazon_order_placed_at` |
| 入库时间 | `updated_at` |
| 处理结果 | **仅当处理进度筛选 = 已处理时显示** |
| 操作 | 详情、处理 |

### 4.2 本金状态展示

枚举：`正常` / `待确定` / `待追回` / `已追回` / `已损失`。

| 状态 | 标签色（Ant Tag） | 金额展示 |
|------|-------------------|----------|
| 待追回 | orange | 有金额时标签下橙色金额 |
| 已追回 | blue | 有金额时标签下蓝色金额 |
| 已损失 | red | 有金额时标签下红色金额 |
| 正常 / 待确定 | green / default | 不展示金额 |

规则：**只要该状态填写了相关金额（>0），一级列表标签下就要显示金额。**

### 4.3 售后进度列

- **主状态**（系统计算，非手选「已处理」）：待处理 / 处理中 / 已处理  
- **标识**：转给他人、无新单号、抢单大厅  
- **可编辑**：仅非「已处理」时可点开，选项为：待处理、处理中、无新单号  
- 「已处理」不可手改，由第 7 节逻辑判定  

### 4.4 处理结果列（已处理筛选下）

展示文案：替换单号 / 补单 / 追回本金 / 无需处理 / 已关闭，及副文案（新单号、子订单、追回金额、备注等）。

## 6. 处理抽屉

进入方式：列表「处理」。布局顺序：

1. 当前进度摘要  
2. **业务操作**  
3. **商务结果**  
4. **本金情况**（始终展示，可不选业务操作直接改本金后确认）  
5. 按所选动作展开的补充区（仅有实际字段时才出现，不再重复刷一遍动作名称）

### 6.1 业务操作

| 动作 | 说明 | 可见性 |
|------|------|--------|
| 补单 | 打开补单弹框，复用工作台编辑组件 | 非「本金多返」 |
| 替换单号 | 填新亚马逊订单号 | 非「本金多返」 |
| 转给他人 | 选择接手业务员 | 非「本金多返」 |
| 放入抢单大厅 | `transfer_to_staff = GRAB_HALL`，进度仍为处理中 | 非「本金多返」 |
| 追回本金 | 展示「本金明细」：实返金额、后台实付金额（横排短展示） | **仅订单状态 = 本金多返**；此时业务操作区**只保留**该按钮 |

### 6.2 商务结果

| 动作 | 说明 |
|------|------|
| 关闭 | `issue_status = 已关闭` |
| 无需处理 | `issue_status = 无需处理` |
| 撤销 | 确认后**真删**（mock 从本地列表删除；非 mock 对 `after_sale_issues` 执行 `delete`） |

默认本金建议（选动作时带出，可再改）：

| 动作 | 默认本金状态 |
|------|----------------|
| 替换单号 | 正常 |
| 补单 / 关闭 / 无需处理 / 转给他人 / 放入抢单大厅 | 已损失 |
| 追回本金 | 已追回 |
| 撤销 | 正常 |

### 6.3 本金情况（独立区块）

- 本金状态枚举（各订单状态均可选）：正常、待确定、待追回、已追回、已损失  
- 待追回 → 待追回金额 + 备注  
- 已损失 → 损失金额 + 备注  
- **已追回** → 已追回金额 + **追回方式**（直接退回 / 新订单抵消）+ 选抵消时 **抵消子订单ID** + 备注  
- 可不选任何业务/商务动作，只改本金后点「确认操作」

### 6.4 补单弹框

- 复用 `SubOrderWorkflowEditor`  
- 需选择补单买手；可填新亚马逊订单号  
- 提交时：有新单号 → `issue_status = 已补单` 且可算已处理；**无新单号 → `issue_status = 处理中`**（不加「无新单号」标识，除非本身就是无新单号状态）

### 6.5 替换单号

- 新订单号必填，且必须与旧订单号不一致  
- 成功后 `issue_status = 已替换单号`，并尽量同步原子订单 `amazon_order_id`

---

## 7. 「已处理」判定逻辑（系统自动）

进度列「已处理」**不可手选**，由下列规则判定：

| 场景 | 算已处理的条件 |
|------|----------------|
| 替换单号 | 新订单号已更新，且与旧订单号不一致；`issue_status` 为已替换单号 |
| 补单 | 存在补单子订单信息，且新子订单已有亚马逊单号（有单号才算；无单号保持处理中） |
| 追回本金 | 本金为已追回且金额 > 0，或 `issue_status = 已追回本金` 且金额 > 0 等 |
| 无需处理 / 已关闭 | 提交对应动作后即已处理 |
| 撤销 | 单据删除，不再出现在列表 |

转给他人 / 放入抢单大厅后仍为**处理中**；若后续补单且有新单号，再进入已处理。

## 8. 关键字段与存储说明

### 8.1 表 `after_sale_issues`（迁移基线字段）

常见字段包括：`issue_number`、`sub_order_id/number`、`order_id/number`、`buyer_*`、`staff_*`、`customer_name`、`asin`、`issue_type`、`issue_status`、`principal_*`、`old/new_amazon_order_id`、`replacement_*`、`profit_diff`、`loss_amount`、`description`、`resolution_notes`、`resolved_at`、时间戳等。  
后续迁移另有 `principal_status`、`principal_reason`、客户返款相关字段等。

### 8.2 前端 / mock 常用扩展字段

| 字段 | 用途 |
|------|------|
| `country` | 国家筛选与币种 |
| `transfer_to_staff` | 转交对象或 `GRAB_HALL` |
| `principal_status` | 本金状态 |
| `recovered_amount` / `recovery_method` / `recovery_new_sub_order_number` | 追回金额与方式；写库时部分扩展字段会从 DB update 中剥离，以 mock 与 `principal_*` / 备注为主 |
| `actual_paid_usd` / `refund_amount_usd` 等 | 实付、实返展示 |

### 8.3 `issue_status` 规范映射

| 历史/别名 | 规范值 |
|-----------|--------|
| 已替换订单 | 已替换单号 |
| 已退款给客户 | 无需处理 |
| 需补单 | 无新单号 |

常用过程/结果值：待处理、处理中、无新单号、已替换单号、已补单、已追回本金、已关闭、无需处理。

## 10. 操作按钮默认本金与提交要点（摘要）

| 操作 | 关键校验 / 结果 |
|------|------------------|
| 仅改本金 | 可不选动作；已追回须金额 + 追回方式（抵消须填抵消子订单ID）；仅改已追回时可将 `issue_status` 置为已追回本金 |
| 补单 | 须买手；无新单号→处理中；有新单号→已补单 |
| 替换单号 | 新单号 ≠ 旧单号 |
| 转给他人 | 须选业务员；进度处理中 + 转给他人标识 |
| 放入抢单大厅 | `GRAB_HALL`；进度处理中 + 抢单大厅标识 |
| 追回本金（本金多返） | 本金明细展示实返/后台实付；本金区默认已追回 |
| 关闭 / 无需处理 | 提交即结果态 / 已处理 |
| 撤销 | 确认后删除，列表消失 |

金额类本金状态（待追回 / 已追回 / 已损失）金额必须 > 0 才能保存。
